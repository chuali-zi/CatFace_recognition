# 猫脸检测准备与数据边界

2026-09-22 已开始运行独立于旧 Haar 筛选的检测实验，代码与复跑入口见 [experiments/detection](../experiments/detection/README.md)。下文的数据边界仍有效；不代表已经选定生产检测器或已经有门上识别性能。

## 当前可用的框与关键点

- **CatFLW** 已导入 2,079 张图，带 48 点和 `bounding_box`，是 `[x1,y1,x2,y2]` 原图坐标；`annotation_face_box` 是后续处理中的派生字段。它没有猫身份标签，适合作为检测/关键点的正样本来源，不能用于身份评测。
- **CAT**（`catface`）有约 19,994 条原始记录、9 点标注和 `annotation_face_box`。清理流程保留 7,777 条 CAT 关键点几何候选；但清单仍是 `annotation_review_status=pending_semantic_review`，不是全部已核准的检测真值。
- `data/clean.landmarks.jsonl` 共 9,743 条（CAT 7,777、CatFLW 1,966），只完成格式、边界、重叠和质量筛选，逐点语义审核仍 pending。CAT/CatFLW 同一 `pixel_hash` 的图必须一起划分，不能当作两张独立图。
- `data/clean.identity.jsonl` 是 1,369 张 / 247 个身份的逐张目视检查身份子集。每条记录带原图相对路径和原图坐标 `face_box`，因此可以作为**正样本框的离线 sanity check 或训练候选**；但它的框来自此前 OpenCV 猫脸候选后再人工检查，样本只覆盖“已经被候选器找到”的脸，没有负样本，且来源、身份和相邻帧分布不代表摄像头。不能用它单独测检测召回，也不能把它当独立真值测试集。

清洗报告明确：身份 PNG 与原图框已逐张像素核对，1,369 张输出可解码；但 `session_id` 为空、发布者标签不是现场真值。原图框安全使用前仍应统一 EXIF 朝向/坐标约定，并以 `pixel_hash`、原图路径和身份组做隔离，避免同图或同组泄漏。

## ECPose 的定位

已下载的 MeowID-Base `ecpose.onnx` 是关键点定位辅助模型：输入 RGB 640×640，并输出姿态/关键点相关结果；清理脚本只用它做少量候选定位。它不是已经验证的猫脸检测器，也不是身份模型。当前文档记录的本机 CPU 试跑不适合承担全量主流程；不要因模型文件存在就宣称有检测能力。

## 本轮纯 CPU 候选

本轮沿用现有 Torchvision / OpenCV / ONNX Runtime 环境，比较级联基线和一个可训练轻量检测器：

1. **OpenCV basic / extended 猫脸 Haar**，最长边 320 / 640。开发集另做固定框上下文适配，以处理眼鼻框与 CatFLW 含耳朵框的定义差异；其既有候选框不能回写成真值。
2. **Torchvision SSDLite320-MobileNetV3-Large**，使用官方 COCO_V1 初始化后，以 CatFLW 作者猫脸框做有界微调。COCO cat 原来是猫身，不直接当猫脸；只在微调后评测。本机已经具有匹配的训练与导出依赖，优先验证这一条路线。[官方模型说明](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.detection.ssdlite320_mobilenet_v3_large.html)

早先列出的 YOLOX-Nano / NanoDet 没有实现或训练，不再作为当前操作入口；本轮不同时引入新训练框架。

## 摄像头尚未接入时的离线准备

先做小而可复现的检测评测，不下载大权重、不安装新的运行时：

1. 从 CatFLW/CAT 中只取带 `annotation_face_box` 的记录，按 `pixel_hash` 分组后划分 train/validation/test；先人工抽查每个来源的一小批框，记录框是否真的是猫脸、是否包含多猫。未完成语义审核的记录只能标作候选，不能混进最终测试真值。
2. 将 `clean.identity.jsonl` 的 `original_path + face_box` 作为单独的 identity-positive sanity split，保留 `source/身份/原图 hash`，不与同原图或同身份的检测训练/测试重复。它只回答“在已知清晰猫脸上能否覆盖”，不回答真实场景召回。
3. 补充负样本：无猫室内/门口背景、猫身无脸、玩偶/印刷猫图、窗外/反光和空画面。补充多猫同框并标出每个脸框和“目标不唯一”场景；一张图无猫或多猫不能只用正框格式表达。
4. 补充困难正样本：小脸、侧脸、俯仰、遮挡、运动模糊、逆光/夜间红外或低照度、不同距离和门口真实视角。公开 CAT/CatFLW 只能作为起点，不能替代真实摄像头分布。
5. 统一记录输入尺寸、缩放/填充、阈值、NMS、单猫/多猫判定和每张图的检测结果。报告 AP/Recall/precision 之外，至少报告小脸与夜间子集召回、空画面误报率、多猫漏报率；检测框只作为后续身份模型输入，不能把身份准确率当检测指标。

## 端侧必须实测的项目

在飞腾派上用固定图片和固定线程数分别测 FP32（及确实支持的 INT8）：模型加载时间、预热后 P50/P95 单帧延迟、峰值内存、输入解码/缩放/NMS 的时间占比、持续运行温度/降频影响，以及多猫图的最坏耗时。记录 ONNX Runtime/其他后端版本和算子兼容错误；不从 x86 结果乘固定倍数推算。只有在检测覆盖率和误报满足门口输入要求后，才接入 MobileNetV3 身份特征实验。

## 建议的下一步

现在使用固定 CatFLW 训练/开发/留出划分，运行 Haar 与 SSDLite 的同数据对照；127 张图已核对完整可见脸框，训练池仍是可能不完整的作者标注。后续已完成275张开发原图的检测裁剪身份重校准，见[裁剪报告](crop-study-2026-09-22.md)，但仍需真实无猫、多猫和机位数据。公共图检测与开发集校准的全流程重放不能宣称门上识别率。
