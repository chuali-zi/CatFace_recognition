# 本机完整画面猫脸检测对照 · 2026-09-22

本轮完成了独立于旧 Haar 筛选的数据划分、128 张图目视复核、轻量检测器 CPU 微调、ONNX 导出及冻结配置的图片级留出检查。
**SSDLite 猫脸候选明显改善标注脸的覆盖率，仍是研究模型，不是已验收的门口识别模块。** 身份模型未在本轮改动。

代码与完整命令见 [检测实验说明](../experiments/detection/README.md)；本机实际输出在 `experiments/runs/detection-cpu/`。

## 数据与结果的含义

- CatFLW 全部 2,079 条原始记录，合并同像素后 2,071 张。没有用 Haar 是否命中筛选。
- 使用像素 hash 与直接/镜像 dHash 距离≤4的连通分组，共 2,067 组；seed=20260922 按组划分训练 1,447、开发 312、test 312 张。
- 文件名前缀不是猫身份或拍摄场次，未用它生成身份/场次标签。这里只减少显式重复泄漏，不能保证找全转载、裁剪和跨来源同猫。
- 同像素重复文件可能对同一脸给出略不同的框；IoU≥0.75 保留路径排序靠前的作者框，没有把同一脸重复当作两个目标。
- 原始 `bounding_box` 为 xyxy，所有所用 CatFLW 原图 EXIF orientation=1。不用关键点，不将 48 点视为已逐点审核。
- 作者可能只标了同框的一只猫。全量数据只能报告**已标注脸覆盖率**，不能把额外预测自动算成误报。
- 在运行预测前按固定种子选开发64、test64张完整画面，逐张查看含作者框的缩略图，歧义图再看原图。一张 test 有镜面猫脸，保留为非完整标注；其余开发64、test63张各一张可见猫脸，形成 exhaustive 子集。决定保存在 `experiments/detection/review-decisions.json`。
- 公开图以大脸为主：test312 中面框面积占比≥5%的有305张，1%–5%的有7张，<1%的没有。没有夜间机位、空门口背景或可靠来访事件数据，不能证明小脸/无猫误报率。

“独立”仅指没有沿用本仓库旧的 Haar 正样本筛选。OpenCV、COCO、ImageNet 的训练图与这些公开图片不一定没有重合；这不是完全可证明未见图片的评测。

## 开发过程与冻结规则

Haar 固定 scaleFactor=1.1、minNeighbors=3、minSize=32，比较 basic/extended × 最长边320/640。直接原框在开发312张只有9–20个 IoU≥0.5匹配，原因不仅是漏检，还包括 Haar 眼鼻框小于作者含耳朵的框。

随后只添加一个固定框定义对照：宽高×1.5，中心上移原高度×0.15，裁到原图边界。开发312张的匹配为 basic320 173、basic640 151、extended320 177、extended640 151；在人工开发64张上，extended320的 F1 最高，选为 Haar 冻结参照。这个变换不是新检测能力，也不能直接继承旧身份裁剪的阈值。

轻量网络使用 [Torchvision SSDLite320-MobileNetV3-Large 官方 COCO_V1](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.detection.ssdlite320_mobilenet_v3_large.html) 初始化。COCO 原类别17是猫身；本次确实用作者猫脸框微调后才做猫脸评测。

- 保留91类头，class17改学脸框；只解冻最后一个主干特征块和检测头。
- 所有 BatchNorm running stats 冻结，验证不更新状态。未标注脸可能被标准 SSD loss 当作背景，是当前训练的局限。
- CPU4线程、batch8、AdamW 1e-3、weight_decay=1e-4、seed20260922，真实完成8轮。
- 按开发 loss 选择第3轮，开发 loss=1.50131；第8轮=1.60902，没有直接选最后一轮。
- 图像 RGB/PIL bilinear 拉伸320×320，/255；网络内部 mean/std均为[0.5,0.5,0.5]，不是身份模型的 ImageNet 归一化。
- 只在人工开发64张比较 score阈值0.3/0.5/0.7，其 TP/FP/FN 分别64/8/0、63/4/1、62/1/2，按最高 F1 选择0.7。
- 固定0.7、NMS IoU=0.55、top-k=300、最多10框后，才运行 SSDLite test。不据 test 结果继续调整。

开发全部312张在阈值0.7下匹配299张（95.83%）；初始0.3的308/312不是最终配置的成绩。

## 冻结配置的留出结果

匹配均为原图坐标、一对一 IoU≥0.5；不是 AP。

| 数据 / 指标 | Haar extended320 + 固定框适配 | SSDLite320 猫脸，score≥0.7 |
| --- | ---: | ---: |
| test 全部312张：标注脸匹配 | 185/312（59.29%） | **302/312（96.79%）** |
| test 全部312张：没有预测框 | 123张 | 7张 |
| test 全部312张：多预测框 | 3张 | 5张 |
| 人工test63张：TP / FP / FN | 44 / 1 / 19 | **60 / 2 / 3** |
| 人工test63张：precision | 97.78% | 96.77% |
| 人工test63张：recall | 69.84% | **95.24%** |

SSDLite 提高了覆盖，但不是所有方面都更好：人工 test 多了一个 FP；而且多框时重放会返回 `unusable`，不会挑一个看似方便的框继续识别。因此检测 recall 不等于最终可用帧比例，也不等于身份正确率。

复核失败图后，3个FN中2个是真正没有输出（花纹沙发黑白猫、草地暗色小猫），另1个是定位框太宽，IoU仅0.371。2个FP分别是同一只猫的重复框、上述过宽框，并非找到两个无关背景物体。没有据此改真值、阈值或NMS。在这63张单猫图里，同时满足“正确匹配且只有一个预测框”的是59张；其余4张不会构成可靠单猫裁剪入口。

无猫负样本没有补齐。本轮从隔离 re-ID 池固定查看32张不同像素候选，它们仍基本包含猫，未据“广告/隔离”标签把它们改成无猫样本，未报告 no-cat FPR。

逐图输出：`haar-selected-test/`、`haar-selected-reviewed-test/`、`ssdlite-test/`、`ssdlite-reviewed-test/`。开发阈值选择另见 `threshold-selection.json`。

## 本机CPU代价

Windows11 / Intel Core Ultra7 155H / Python3.12.10 / ONNX Runtime1.20.1 / OpenCV4.14.0。训练和准确率评测结束后，3轮轮换顺序、共9个独立进程串行测量；各配置均2线程，预热20次、实测100次，循环相同20张已解码开发图片。

| 配置 | 单帧P50（3轮范围） | 单帧P95（3轮范围） | 进程峰值RSS |
| --- | ---: | ---: | ---: |
| Haar extended320 + 固定框适配 | 12.75–13.38 ms | 17.54–18.07 ms | 165.2–165.9 MiB |
| SSDLite320 ONNX检测 | 14.49–15.47 ms | 16.68–17.28 ms | 123.1–123.4 MiB |
| SSDLite检测 + Large224身份 + 图库匹配 | 24.85–27.43 ms | 46.00–51.78 ms | 152.3–154.5 MiB |

pipeline每轮100/100次实际执行身份阶段，条件身份+匹配P95=15.07–17.82ms；这批无身份真值的CatFLW图全部输出unknown，只记录执行分支，不作为拒识正确率。
模型初始化分别约31–34 / 160–164 / 220–248ms。

这些是**预解码图片**的运行时间，进程峰值含已解码图片缓存和模型加载；不含相机、文件解码和长时间温升。不能相加两个单模型P95充当pipelineP95，表中pipeline是真实串联测量。
原始高分辨率手机照片的PIL缩放、裁剪及解码可能远高于这里的公开图成本；单张4096级原图实验重放确实更慢。不能据表直接宣布门口FPS，更不能外推飞腾派。

## 导出与重放

最终检测 ONNX 为13,834,067 bytes（约13.19 MiB），固定1×3×320×320，图内完成归一化、框解码及跨91类 softmax，只输出class17分数；NumPy侧完成NMS和原图坐标还原。

用开发前5张真实图片对比官方 PyTorch 完整输出与 ONNX+NumPy，阈值0.7下5个框数量全部一致，最大框差6.10e-5像素、最大分数差1.19e-7。这个结果只验证导出一致性，不是检测准确率。

`experiments.detection.replay` 将新检测器接到冻结的 Large224 身份候选：无框为 `no_cat`，多个候选为 `unusable`，单框再提取身份特征。此检测阶段使用旧crop图库，输出带 `diagnostic_only` 和“未做端到端校准”的提示；旧图库的身份阈值没有因换检测器自动变得有效。后续已完成开发原图重登记/重校准，详见[裁剪与身份对照](crop-study-2026-09-22.md)，当前研究包改用重校准的head图库，仍非现场验收。

已生成 `experiments/runs/catid-edge-detection-research.tar.gz`（14个文件，约22.76 MiB）。独立解包后用真实原图重放，核对模块确实从解包位置加载、运行没有导入Torch；同时全部74项自动测试通过。这验证交付可运行，不作为身份准确率证据。

原始训练图片没有删除。数据来自 [CatFLW 作者仓库](https://github.com/martvelge/CatFLW)，标示CC BY-NC 4.0；本轮产物限研究验证，没有完成商业使用授权核查。生产前还要用可用授权、真实机位数据重新核验。
