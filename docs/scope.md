# 识别模块的职责与接口

## 职责

输入图像，完成猫检测、有效图像选择、身份特征提取、与登记猫比较和陌生猫拒识。后续可以支持同一目标的多帧确认。身份登记样本及其特征属于识别模块的数据；通行权限由调用方管理。

门锁、电机、GPIO/UART、开关门状态、通行授权、用户账号、设备绑定、事件通知、OTA、Web 控制台和整机部署由其他项目负责。

## 当前交接约定

`src/catid/contracts.py` 定义 Python 接口。调用方传入 JPEG/PNG 等编码图像的 `bytes`；具体后端在初始化时配置模型和登记库。当前只定义 `recognize` 方法，没有默认后端。

| 状态 | 含义 | cat_id | score |
| --- | --- | --- | --- |
| `known` | 达到当前模型校准条件的已登记身份 | 必填 | 必填 |
| `unknown` | 有可用于比较的猫，但无法接受为任何已登记身份 | 空 | 可提供最高匹配分数 |
| `no_cat` | 没有检测到猫 | 空 | 空 |
| `unusable` | 图像不满足识别条件，如模糊、遮挡、多猫目标不明确 | 空 | 空 |

`unusable` 必须说明 `reason`。`score` 是该后端的匹配分数，不默认为概率，也不能跨模型直接比较。模型更新后必须重新校准，并确认登记特征兼容性。

模型文件缺失、运行时错误、输入无法解码等作为错误向调用方报告，不返回假的 `known`。是否重试由调用方决定。

第一版以单猫图像为目标；多猫且无法确定目标时返回 `unusable`。将来若需要逐目标结果，再根据真实输入扩展接口。

这个接口不含“是否允许通过”，也不触发任何外部设备。接口是后续实现的约定，不能实例化成一个可工作的识别器。登记库格式、传输协议和模型发布方式等到首个有效候选确定后再落实。

## 代码放置

- `src/catid/`：稳定接口和跨路线通用工具，后续接纳经过验证的识别实现。
- `experiments/`：正在比较的识别候选及其运行说明。
- `data/`：原始数据、样本清单、清洗结果。
- `docs/`：同一套有效说明，避免多篇文档给出冲突的“当前最佳方案”。

没有在默认包中加载的研究模型；基础依赖目前仅 Pillow。训练或推理依赖放在 `experiments/identity/requirements*.txt`。实验提供裁剪猫脸 known/unknown 图片重放、Haar对照，以及SSDLite完整图片的原图登记、开发集身份校准与重放。检测器、裁剪方式及登记库必须保持一致，修改后需重校准。当前公开图研究仍未同时解决正确接受与陌生拒识，没有现场验收或飞腾派测量；它们尚未实现或替代主包的生产后端。
