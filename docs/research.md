# 识别路线整理与下一轮实验

## 当前结论

当前没有选定生产识别路线。2026-09-22 已在 [experiments/identity/](../experiments/identity/README.md) 新实现 MobileNetV3-Small 160 的预训练特征、简单分类微调与 ONNX CPU 对照，真实结果记录在[端侧准备报告](edge-readiness-2026-09-22.md)。旧实现及旧权重没有沿用。

下面对旧路线的判断来自 2026-09-17 清理前本地代码和已有诊断记录的核对；不是新模型的性能实验。新候选的实现、评测和实际边界以上述 2026-09-22 报告为准。

## 旧路线的处置

| 路线或组件 | 已发现的问题 | 本次处理 |
| --- | --- | --- |
| EfficientNet-Lite0 分类 logits + 颜色直方图 + LBP | 身份检索依赖通用分类输出和手工拼接，预处理与服务耦合；没有可信现场验收 | 删除实现、配置和权重，不作为默认基线继续维护 |
| MobileNetV2 分类输出 | 同属通用分类输出路线，没有独立有效结论支撑保留 | 删除 |
| 颜色/LBP 单独识别 | 花色与背景容易混淆，不能证明同花色个体区分能力 | 删除 |
| 启发式取猫身上半部作为猫脸 | 输入语义不稳定，对网络图可能切掉身份信息 | 删除 |
| 旧 MobileFaceNet + Sub-center ArcFace | 本地旧训练只做过少量 epoch；训练身份与部分测试重叠；训练数据存在重复和冲突 | 删除训练实现及全部 checkpoint，不沿用旧权重 |
| Ridge 关键点回归与对齐 | 训练与推理裁剪不一致，已有诊断显示加入对齐反而变差 | 删除模型、训练器和对齐流水线 |
| 动态 INT8 CNN | 旧本机运行出现 ConvInteger 不支持 | 删除量化脚本和产物 |
| YOLOv5n@640 猫身检测 | 检测开销占大头，猫身框不等同于猫头；旧模型含 FP16 CPU 路径问题 | 随旧流水线删除，后续重新比较检测候选 |
| EfficientNet 池化特征导出候选 | 曾作无训练对照，但没有稳定部署结论 | 删除派生模型与专用脚本；保留“预训练特征基线”这个实验问题 |
| 旧随机切分与分散评测工具 | 受缓存、重复图片、训练身份重叠影响，旧 FAR 分母曾混入非陌生查询 | 全部删除，使用统一的逐查询开集指标 |

## 实验顺序

### 1. 先把可比较的数据准备好

当前已放行的猫脸入口为 `data/clean.identity.jsonl`：1,369 张 / 247 个身份，全部输出候选经过目视检查，见[内容清理报告](data-cleaning-2026-09-17.md)。`python -m catid prepare data/samples.expanded.jsonl` 生成中间机械候选，不能代替后续内容清理。规则见[数据说明](../data/README.md)，来源见[来源记录](data-sources.md)。re-ID 的广告、列表页和身份冲突样本继续隔离。CatFLW 与 CAT 分别提供 48 点、9 点标注，不提供身份。

继续核验被隔离的身份疑点、修复未放行的猫脸裁剪，逐点核对关键点候选。为现场采集建立真实拍摄日期或来访事件标签。CAT/CatFLW 仅用于关键点/检测任务。保守猫脸子集减少了姿态与来源覆盖，后续需补充同花色、夜间、小脸、侧脸和遮挡等真实困难条件。

训练身份与未见身份评测隔离；已登记猫的注册、校准与测试图按场次隔离；校准陌生猫和测试陌生猫的身份也隔离。互联网来源前缀只能避免字符串碰撞，不能证明不同来源不存在同一只猫。

没有场次信息的公开图实验只能称为图片级诊断。不要用它证明真实来访事件的错误率。

### 2. 先建立一种简单基线

先比较固定猫头/全身裁剪与一种通用预训练特征。每猫注册 3/5 张、图库 2/5/更大规模可作为初始矩阵，样本不足直接记录不足。所有候选使用相同样本 ID 和划分。基线的作用是检验数据和评测流程，并建立后续训练的对照。

### 3. 再训练轻量身份模型

从一种有预训练初始化的小 CNN 开始，采用简单的身份训练目标。把随机种子、身份清单、输入尺寸、增强、训练步数和导出预处理写在实验说明中。分类验证准确率只反映训练身份内部分类，选型要看预留身份的注册/查询任务。

一次只改变一个关键变量。不要在没有基线的情况下同时引入复杂对齐、多路融合、蒸馏和量化。

### 4. 单帧结果成立后再做现场和端侧实验

先测检测覆盖率与身份拒识，再测同一目标多帧。用真实飞腾派记录检测、特征、图库匹配和完整识别耗时，预热后测 P50/P95、线程数、峰值内存和持续运行表现。不能从 Windows/x86 耗时按固定倍数推算板端速度。

检测输入、线程数、FP32/INT8 的收益都需实测。小模型文件不保证低运行内存；INT8 也不保证在目标 CPU 上更快。

## 每次实验最少留下什么

一个可运行命令、一份简短的实验说明、使用的数据/划分与模型来源、逐查询预测和统一指标。端侧实验额外记录设备与实测耗时。原始权重和输出放在 `experiments/runs/`，不放进 Python 包或文档目录。

失败实验在本文件补充结论，废弃代码与产物直接删除。有效候选经同协议比较后再进入主模块。当前新实验均留在 experiments 中，不能继承旧模型的性能结论。

## 2026-09-22 新实验结论

MobileNetV3-Small 160 的普通分类微调已跑满 30 轮，但开发集未显示明确收益；静态 QDQ INT8 则造成较大身份接受率损失。FP32 基线最终图片级留出测试的已知正确接受为 21/23，陌生猫误认为 15/121，拒识未达标。继续使用 FP32 做后续研究与板端性能参照，尚不进入 `src/catid/`。完整分母、阈值和运行环境见[实测报告](edge-readiness-2026-09-22.md)。

追加相同预算的 ArcFace 30 轮对照后，单组开发图库正确接受提高至 25/29、已知错认 0/29、陌生误认降至 1/120，因此当时将 **MobileNetV3-Small + ArcFace FP32** 列为优先验证候选。样本量和场次边界没有因此消失，不将该开发分数当作门口验收；后续图库实验已经更新这一优先级，见下文。

该候选在同一个已曝光 test 分区补测：陌生误认降为 0/121，但已知正确接受仅 11/23。当前拒识与可用率尚未同时满足目标，不能宣布模型选型完成。保留候选继续验证登记姿态/图库汇总与困难陌生猫的分布，而不是根据已看过的 test 调阈值。

## 后续图库稳定性结果

在固定 49 个开发身份、275 张猫脸内完成 2/5 猫、3/5 张登记图、10 个种子的重复对照，以及固定所有查询和陌生猫的严格登记配对。平均原型/余弦的重复图库宏平均 DIR/FPIR：未微调基线 82.8%/2.96%，普通分类 76.6%/3.52%，ArcFace 72.3%/3.77%。重复图片不构成新增独立样本，本轮未再读取 test 进行调参。

ArcFace 单组开发优势没有稳定保持；逐张最大匹配和第一二身份分差也未形成稳定收益。因此当前继续使用 **未微调 FP32 + 平均原型/余弦**作为研究与板端测量参照，不把它当成已达标模型。配对实验中增加登记图能改善基线正确接受，但陌生误认仍约 3%。完整设置与结果见[图库稳定性报告](gallery-study-2026-09-22.md)。后续优先核验更有效的身份表征和困难样本，不继续叠加未验证的匹配规则。

## 本机主干/尺寸对照

服务器暂不可用时，已完成官方 ImageNet V1 Small/Large × 160/224 四组合的真实开发评测。Large-224 在重复图库中的宏平均 DIR/FPIR 为 90.18%/2.57%，Small-160 为 82.75%/2.96%；严格登记配对分别为 92.10%/2.17% 和 80.09%/3.06%。这是同一开发图片池的探索性对照，不是新的独立测试。

Large-224 列为精度候选，Small-160 继续保留为速度参照。本机 Large-224 特征 P95 为 6.17–7.19 ms、Small-160 为 2.09–2.36 ms，不能外推飞腾派。原固定开发图库的两张已知错认仍存在，陌生误认仍为 3/120，尚不进入 `src/catid/`。分项结果、反例、成本与复跑命令见[主干对照报告](backbone-study-2026-09-22.md)。

追加 Large-224→Small-160 的批内余弦关系蒸馏，已在本机 CPU 完整训练 30 轮；按训练身份留出图误差选择第 13 轮。学生重复图库宏平均 DIR/FPIR 为 78.27%/2.46%，严格登记配对为 79.08%/2.68%，正确接受低于未微调小模型，没有取得净收益，不升级为端侧默认。继续保留 Small-160 速度参照和 Large-224 精度候选；这不等于已经解决拒识或证明蒸馏普遍无效。

## 完整原图裁剪与身份重校准

冻结检测权重、score0.7和两种身份模型，在原有49个开发身份/275张原图上完成旧裁剪、旧登记+新查询、统一新裁剪的配对对照。273图有单一候选，1图无框、1图多框；多框实为两猫，未用参考框挑目标。登记失败的1组明确标记不可用，比较使用共同39组；查询失败保留在分母并单独报告，不假装为成功拒识。

Large224共同39组DIR/FPIR：旧裁剪92.02%/2.23%；旧登记+新猫头查询即使重校准也只有49.29%/3.04%；统一新猫头裁剪82.87%/2.41%。追加唯一固定几何对照：猫头宽高取2/3、中心下移原头框高度0.1，不按参考框调节，统一使用后为89.36%/2.61%。它提高了宏平均接受率，却未改善陌生误认，且固定5猫图库正确接受从24/29降到21/29，不升级为默认。Small160相同对照也没有同时改善两项指标。

因此继续保留head为研究重放默认、face_core为可复现对照；已把评测、原图登记、重放的裁剪实现统一，登记库绑定检测权重及阈值配置。此次只用development，不再用已曝光identity test选择路线；旧身份池经过Haar筛选，不构成新检测器的独立召回评测。更换检测器后必须重做登记/校准，不能继承旧图库的成绩。详细分母、反例和命令见[裁剪报告](crop-study-2026-09-22.md)。

## 2026-09-26 统一裁剪训练对照

冻结检测器，离线整理826张train/validation原图；814图单框，10图无框，2图多框。为使训练/验证身份成对可用，两臂统一保留145身份、666训练图和145验证图，仅改变旧审核PNG与新head裁剪输入。Small160从相同ImageNet初始化，以相同seed、CE、30轮和优化参数分别训练，按训练身份验证损失选模型，不用开发身份选epoch。

同39组完整原图登记/校准/查询，未微调Small160 DIR/FPIR为72.72%/1.34%；旧crop训练为42.22%/2.39%；新head训练为68.82%/2.86%。新head恢复了训练/推理裁剪错配造成的部分损失，但没有超过未微调参照，也没有稳定解决陌生拒识。其Top-1为97.78%仍不能代替DIR，部分陌生身份划分出现35/138误接受。固定单图库的21/29正确接受不能覆盖重复图库的负面结论。

因此不更新默认研究包、不继续仅凭分类验证分数叠加训练轮数；保留此次同样本对照用于排除简单假设。后续应优先处理更有代表性的身份/难例数据及真正的开集分离问题，不能把已曝光开发池的重复抽样当新增样本。代码增加的仅是离线整数crop_box读取和准备脚本，未增加端侧网络分支。详情及复跑命令见[统一裁剪训练报告](head-adaptation-2026-09-26.md)。

## 同日 CPU 预处理优化

冻结模型与图库，消除读取/重放/身份预处理之间已转正RGB图的重复像素复制。275张完整开发原图的全部非计时输出与改动前一致；8种EXIF方向和多种颜色模式保持像素级一致。高分辨率20图的本机P50/P95从166.44/234.72 ms降到115.79/168.12 ms，CatFLW较小图另做三轮计时。速度收益随原图尺寸而变，不外推飞腾派；准确率与拒识结论不变。这次仅更新研究包运行时代码，不替换任何权重或图库。见[预处理优化报告](preprocess-optimization-2026-09-26.md)。

## 冻结特征的训练集适配

使用相同Large224/head输入，仅在145个训练身份/666张train图拟合均值及同猫pair差分协方差；validation/development/test不参与拟合。预先固定原特征、仅中心化、128维监督白化（收缩系数0.1）三组，不按开发结果追加参数搜索。原特征40个episode完整复现既有结果，共同39组DIR/FPIR分别为82.87%/2.41%、84.04%/2.48%、90.25%/2.87%。白化有正确接受收益，但提高陌生误认，并出现13.77%误认的困难图库，固定图库正确接受也从24/29降到23/29；不更新默认模型或研究包。

下一步优先使用新身份数据复核，避免继续消耗同一开发池。已从现有prepared individuals清单定位完全未进入edge160协议的150个发布者身份/2,465张原图候选，其中123个身份至少8图；仍需视觉、跨标签及近重复检查，尚未加入clean。详细方法、逐查询产物、成本和局限见[线性特征适配报告](metric-study-2026-09-26.md)。

## 新标签图片池的固定候选确认

已从上述候选固定抽取40组/320张原图并逐组查看，未用身份分数选图。跨旧标签复核有1组可能同猫异名，整组8张隔离，保留39组/312张研究池，未并入clean。登记从清楚且单框的图片取每猫3张，其余查询保留暗光、模糊、漏检和重复框失败。每组5猫、25张已登记查询、136张陌生校准、136张陌生查询，校准与查询陌生身份隔离；10组是同池重采样，不是独立来访。

四臂10/10组均完成。Small160原特征、Large224原特征、Large仅中心化、Large白化128维的DIR/FPIR依次为59.60%/1.40%、73.60%/2.28%、70.00%/3.46%、67.60%/5.59%。白化未在新标签池保持旧开发收益，最差组误认28/136（20.59%），不升级默认、不追加参数搜索。仍保留Small速度参照、Large原特征精度参照，尚无生产模型。

另明确发现4个同一前景猫头的重复候选框，其中3张保留在评测池，未手工选框救回；33张无框图也真实可见猫。后续围绕重复框及困难输入改进时，应在训练/开发部分验证，不能反复使用已曝光新池仍称独立验证。完整逐查询、画质分组及边界见[新身份对照](fresh-identity-study-2026-09-26.md)。
