# 摄像头采集与现场验证协议

本协议用于把图片级身份实验推进到真实门口输入。它不指定摄像头型号，也不把公开数据或当前离线结果当作现场性能。原始图像和真实场次记录应保留，后续模型才能复核裁剪、检测和身份判断是否一致。

## 采集方式

固定门口机位、镜头方向和主要 ROI（猫通常出现的区域），记录安装高度、视角、分辨率、帧率、曝光/红外状态和图像时间。验证期间不要按结果挑图；应连续记录来访事件，再从事件中按预先规则抽帧。每个 `session_id` 代表一次真实、连续的拍摄场次或来访事件。可以用日期编码命名，但不能仅从文件名或日期推断场次，更不能把每张相邻帧赋成独立场次。

初始每只已登记猫准备 3–5 张注册图，注册图至少来自 2 个不同场次；另留至少 2 个不同场次作为查询。注册与查询要按场次隔离，同一连续视频片段不能同时出现在两边。陌生猫应来自与已登记猫不同的身份和场次；只有少量陌生猫时，低误认结果只能算诊断，不能据此估计稳定的陌生猫误认率，需继续积累独立事件。

有意覆盖以下条件，并在记录中标明：同花色或外观相近猫、正面/侧脸/俯仰、远近小脸、遮挡和运动模糊、白天/夜间或低照度、逆光、空画面、猫身无脸、玩偶或印刷猫图，以及两只以上猫同框。多猫且无法确定目标应验证为 `unusable`，不能为了提高身份命中率只保留容易的单猫帧。

## 建议的记录表

下面只是可复制的 schema 示例，不是仓库中的真实数据，也不能用示例值代替现场记录：

```csv
image_path,event_id,session_id,capture_time,site_roi,source_kind,true_cat_id,scene,lighting,multi_cat,target_visible,usable,notes
camera/2026-10-01/e001_0001.jpg,e001,s2026-10-01-a,2026-10-01T18:42:10-04:00,door-left,registered,cat-01,single_cat,day,0,1,1,front view
camera/2026-10-02/e014_0003.jpg,e014,s2026-10-02-b,2026-10-02T23:11:04-04:00,door-left,stranger,stranger-01,multi_cat,night,1,0,0,multi-cat target unclear
camera/2026-10-03/e022_0001.jpg,e022,s2026-10-03-c,2026-10-03T07:05:31-04:00,door-left,empty,no_cat,empty,backlight,0,0,0,empty doorway
```

`true_cat_id` 只在人工或可靠登记记录确认时填写；陌生猫使用稳定的匿名个体标签，同一只陌生猫跨事件保持同一标签，确保校准与测试陌生身份隔离。无法确认是否同一猫时记录疑点，不凭事件编号制造独立身份。空画面填 `no_cat`。`usable` 是事后标注的图像是否适合身份判断，不是模型预测。原图路径、裁剪框、模型版本、阈值和每次推理输出应能互相追溯；不要覆盖或只保存裁剪图。

## 验证顺序与报告

先单独统计检测：空画面误报、单猫漏检、小脸/夜间/逆光召回、多猫候选数和 ROI 外误报。再在同一批事件上统计身份：已登记猫正确接受、陌生猫误认、没有猫误触发，以及多帧确认需要的等待时间。注册、阈值校准和最终测试必须按事件隔离；同一只猫的不同场次可以用于泛化测试，但不能把连续帧当成独立事件。

报告至少包含每类事件数量、失败样例路径、`session_id` 分布、检测/身份/整流程耗时和设备环境。先在服务器完成可重复的事件级离线报告，再在飞腾派实测解码、检测、裁剪、特征、图库匹配和多帧确认各阶段的 P50/P95、峰值内存、线程数及持续运行表现。暂定工程目标是身份推理 P95 < 100 ms、整流程 P95 < 500 ms；这是待实测和调整的预算，不是当前能力承诺，也不能用 x86 计时按比例推算板端结果。
