## 已记录的问题

当前逐文件记录包含 **185 张身份候选图、64 个身份**的明确内容问题，另有 **1 条关键点标注待复核**。身份问题是已记录的下限，不是本次所有可疑图的穷尽统计。

| 问题 | 已记录图数 | 含义 |
| --- | ---: | --- |
| 多猫同框、未指定目标区域 | 172 | 包括另一只猫只有部分身体入镜；无法仅凭整图标签确定模型应该学谁 |
| 严重模糊 | 11 | 明显运动模糊或失焦，猫脸细节不可辨 |
| 未见猫的误拍 | 1 | 已查看原图 |
| 没有可用猫脸的局部入镜 | 1 | 人物为主体，只有模糊局部猫头 |
| 笼门遮挡且失焦 | 1 | 猫存在，但猫脸不可用 |
| 重合关键点坐标待复核 | 1 | 眼睛与耳根点坐标完全相同 |

问题类型可以重叠；上表不能相加当成独立图片数。多猫图也不等于永久废图：若能明确标签对应哪只猫，标目标框并裁剪后可能可用。当前缺失的是这种目标对应关系。

### 1. 多猫问题不是零星遗漏

`individuals:0138` 当前保留的 **12 张全部多猫同框**，是粉色笼内两只猫相互重叠的连续照片。此前只隔离 `0138_003.JPG`，没有处理同身份其余图片，说明逐文件修补不足以解决整组拍摄的问题。

其余已记录实例分布在多个身份中，详见 CSV；不是只发生于 `0138`。例如 `0480`、`0485`、`0508` 等冲突关联组有连续的多猫画面。整图直接按单个身份训练，可能学到另一只猫或笼子、背景。

### 2. 无效画面仍进入身份候选集

- `0141/0141_000.JPG`：原图是倾斜模糊的地面、人的腿，未见猫。
- `0496/0496_000.jpg`：人物占据主体，底部只见模糊的局部猫耳 / 猫头，没有可辨识猫脸；不能称为整张完全无猫。
- `0066/0066_016.JPG`：严重模糊，无法辨认有效猫脸细节。
- `0035/0035_009.JPG`、`0036/0036_003.JPG`：明显运动模糊。
- `0122/0122_012.JPG`：笼门、门扣遮挡且失焦。

现有尺寸、解码、近常量检查针对整张图片，并未检查“有无猫、目标有多大、猫脸是否清晰、是否被遮挡”。因此这些图通过程序检查并不矛盾，而是当前筛选能力缺了一层。

### 3. 精确冲突处理没有完成身份层面的核验

有 **21 个身份的 295 张保留图**所属标签曾出现在精确跨身份冲突中。此前只隔离冲突图片，其他同标签图片仍进入保留集；这些身份需要整组复核。

视觉检查发现，一部分冲突场景包含两只猫。同一个多猫画面被放进不同身份文件夹，并不能直接证明两个身份应该合并，也不能直接认定其中一个标签错误。必须核对每个标签所指的猫，并关联目标区域。

### 4. 相似连拍没有充分处理，扩大 dHash 阈值也不能直接解决

对保留集使用普通 / 镜像 dHash 扩大到距离 8 后，额外找到 **1,922 对**距离为 5–8 的候选：

- 同身份 **1,326 对**；查看前 36 对，可见大量同场景、同姿态的小幅变化，属于近似连续拍摄。
- 跨身份 **596 对**；查看前 72 对，可见明显不同的猫因为喂食机位、构图和背景相似而被召回。

这些是候选对数，不是独立图片数，也不是确认重复数。不能把 1,922 对都判为重复，更不能直接把阈值调高后一批删除。当前 `session_id` 尚未建立，按图片随机划分会有同一连拍场景跨训练 / 验证的风险；即使去除若干相似帧，也不能代替按拍摄组划分。

### 5. 猫脸数据与身体视角没有明确分开

HSC 保留集包含 **1,151 张 `front`、219 张 `top`**。目视也看到背部、头顶、进食遮脸和猫脸出框画面。目录叫 `front` 不保证每张都有可用正脸。

头顶 / 背部图不天然是坏图，身体重识别可能有用；但不能未经区分就当猫脸识别样本。后续应标明目标区域、可见部位和用途，按最终路线决定取舍。

### 6. 关键点集也没有完成语义验收

当前保留 **10,859 条关键点记录，对应 8,890 张不同像素图像**；部分 CAT / CatFLW 是同图的两套标注，不能当作独立图片随机拆分。

检查 97 条叠加图后，不能据此声称全量标注正确。其中 `CAT_05/00001150_005.jpg` 的第 0 点（眼睛）和第 3 点（耳根）都为 `(209, 232)`。坐标重合已确认，是否标错及如何修正仍需核对点位定义与原图。单纯检查点在图像边界内无法发现这一类问题。

关键点图中也有多猫场景，但已有点位可以指向其中一个目标，不能套用“多猫即身份监督含糊”的规则全部排除。这两种任务必须分开审查。

## 接下来应该怎样清理

1. 先处理已记录的误拍、无可用猫脸、严重模糊样本；对 0138 和 21 个冲突关联身份整组复核，而不是只删几个例图。
2. 对多猫图明确身份对应的目标框；无法可靠确定目标的留在复核队列。裁剪后再检查猫脸大小、清晰度和遮挡。
3. 把连续拍摄归为同一拍摄组，再做相似帧抽稀和训练 / 验证划分。相似度只做召回，不自动判断跨身份应合并。
4. 将猫脸、侧脸、头顶 / 身体、不可用画面区分；关键点集独立核查点位语义。通过这些检查后再导出新的审核版本，并报告实际剩余数量。

当前瓶颈是已有身份数据的目标与标签质量。扩充无身份标签的新猫脸数据不能直接补上这部分，所以本轮优先检查本地数据，没有继续扩大下载量。

## 复现与局限

在仓库根目录设置 `PYTHONPATH=src` 后运行 `python experiments/data_audit/audit.py`，可重建身份总览、冲突关联组、0138 和相似对接触表，并重新计算全量候选搜索。当前关键点叠加表及其选图 JSON 已保留在本地证据目录。`python experiments/data_audit/record_findings.py` 从已保存的接触表索引重建本次观察记录与浏览页；它不重新执行视觉判断。

本轮没有改变候选集，所以原有 10,718 / 550 等数量不变；不能将记录问题后的状态称为“这些问题已经排除”。没有进行模型准确率评测，也没有确认所有未列出图片的身份真实性。
